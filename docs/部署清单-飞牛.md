## 1. 必需的运行时依赖（都在容器外）

| 依赖 | 位置 | 缺失后果 |
|---|---|---|
| docker.sock | 挂载 `/var/run/docker.sock` | 完全不可用 |
| **宿主机同路径挂载** | `- /vol1/1000/docker:/vol1/1000/docker` | Compose 项目路径解析错、编辑保存到错误位置 |
| **docker-compose 二进制** | `/vol1/1000/docker/dockercopilot/.bin/docker-compose` | **Compose 标签整块消失**（接口 `available:false`，前端据此隐藏） |
| Docker Hub 凭据 | `/root/.docker/config.json` 或 `DC_REGISTRY_AUTH` 环境变量 | 私有镜像"永远没有更新" |
| 代理（若 Docker Hub 直连不通） | 容器内 `HTTP(S)_PROXY` | 检测更新全部超时 / 401 |

⚠️ 第 2、3 项最容易漏，且**漏了不会报错**，只是界面少一块功能。

## 2. compose 文件（完整，可照抄）

```yaml
services:
  dockercopilot:
    image: zchjoe/dockercopilot:latest
    container_name: dockercopilot
    network_mode: host
    restart: always
    environment:
      - TZ=Asia/Shanghai
      - DOCKER_HOST=unix:///var/run/docker.sock
      - BACKUP_DIR=/data/backups
      # 只检查关心的镜像，避开 Docker Hub 限流；逗号分隔，子串匹配
      - CHECK_ONLY=zchjoe/procurement-center,zchjoe/nc-bridge
      - CHECK_CRON=*/5 * * * *
      # Docker Hub 直连不通时，走宿主机的代理（与 dockerd 的 daemon.json 保持一致）
      - HTTP_PROXY=http://192.168.1.250:7890
      - HTTPS_PROXY=http://192.168.1.250:7890
      - NO_PROXY=localhost,127.0.0.1,192.168.0.0/16,100.64.0.0/10
      # 私有仓凭据兜底：base64("用户名:token")，不依赖 /root/.docker/config.json
      - DC_REGISTRY_AUTH=${DC_REGISTRY_AUTH}
      - secretKey=${SECRET_KEY:-dockercopilot-local-2026}
    volumes:
      - /var/run/docker.sock:/var/run/docker.sock
      # 让 dc 能读到私仓凭据；fnOS 会周期性重写该文件，配套第 4 节的 systemd 定时器
      - /root/.docker/config.json:/root/.docker/config.json:ro
      - /vol1/1000/docker/dockercopilot/config:/data
      # ⚠️ 两边路径必须完全一致，否则 compose 里的相对路径会被解析成错误的主机路径
      - /vol1/1000/docker:/vol1/1000/docker
```

`SECRET_KEY` 建议放 `.env`；本 fork 的 `local` 分支已去掉后端密码校验，前端会自动登录，
所以 `secretKey` 只作为 JWT 的签名密钥使用（**仍不要外泄**）。

## 3. 安装 docker-compose 二进制（Compose 功能的前提）

镜像里**不含** docker CLI/compose（有意如此：不用为它重建镜像）。dc 直接 exec 宿主上的静态二进制：

```
/vol1/1000/docker/dockercopilot/.bin/docker-compose
```

安装（幂等，可重复跑）：

```bash
sudo bash scripts/install-compose-bin.sh
sudo /vol1/1000/docker/dockercopilot/.bin/docker-compose version   # Docker Compose version vX.Y.Z
```

脚本行为：已存在则跳过；否则按「直连 → 走 7890 代理」两次尝试下载 GitHub Release，
校验为可执行 ELF 后 `install -m 755` 到目标路径。

**验证**：

```bash
JWT=$(curl -s -X POST -F 'secretKey=' http://127.0.0.1:12712/api/auth | sed -E 's/.*"jwt":"([^"]+)".*/\1/')
curl -s -H "Authorization: Bearer $JWT" http://127.0.0.1:12712/api/compose | head -c 120
# 期望："available":true，"projects":[...] 里能看到你的 compose 项目
```

> 这个文件**不在镜像里、也不会随镜像更新恢复**。换机/重装必须重跑本节。

## 4. fnOS 会清空 docker 凭据（必须装自愈）

现象：`/root/.docker/config.json` 被 fnOS 的 `dockermgr/dsmgr` 重写成只剩 `X-Meta-*` 头，
`auths` 整段消失 ⇒ `docker compose pull` 报 `pull access denied`，dc 的私有镜像检测也拿不到 scope。

装一个 5 分钟自愈的 systemd timer（脚本见 `scripts/fix-docker-auth.sh`）：

```bash
sudo bash scripts/fix-docker-auth.sh --install
systemctl list-timers dc-fix-docker-auth.timer      # 应显示 NEXT
```

它做的是**合并**而非覆盖：保留 fnOS 写入的 `HttpHeaders`，只把 `auths` 补回来；
凭据备份在 `/vol1/1000/docker/dockercopilot/.creds/config.json`（fnOS 不碰这个目录）。

> **2026-11-04 路径迁移**：这两样东西原先在顶层 `.dockercopilot/` 与 `.docker/`（两个隐藏目录
> 和已有的 `dockercopilot/` 项目目录并存，顶层显得杂乱）。现在统一放进 dc 自己的项目目录：
> ```
> /vol1/1000/docker/dockercopilot/.bin/docker-compose     ← Compose 二进制
> /vol1/1000/docker/dockercopilot/.creds/config.json      ← 私仓凭据备份
> ```
> 升级步骤：
> 1. 先 `mv /vol1/1000/docker/.dockercopilot/docker-compose /vol1/1000/docker/dockercopilot/.bin/`（没有旧目录就跳过）
> 2. 重跑 `sudo bash scripts/fix-docker-auth.sh --install` —— 它会把旧 `.docker/config.json` 自动搬到 `.creds/`
> 3. 新镜像里的默认路径已是新位置；临时想指回旧位置可用环境变量 `DC_COMPOSE_BIN` 覆盖，不必重建镜像
> 4. 旧目录确认空了就删掉：`rmdir /vol1/1000/docker/.dockercopilot /vol1/1000/docker/.docker`

## 5. 前端：仓库自带的 `front/` 优先

本 fork 的「设置」「Compose」页面在**提交进仓库的 `front/`** 里（约 379KB）。
上游 `dongshull/Docker-Copilot-React@master` 的产物**没有**这两个页面（382KB）。

CI 已加判断：`front/index.html` 存在 ⇒ 跳过上游产物下载。**不要删仓库里的 `front/`**，

## 7. 常见故障对照

| 现象 | 原因 | 处理 |
|---|---|---|
| 导航里没有 Compose | compose 二进制缺失 / 路径不对 | 第 3 节 |
| 导航里没有设置 | 用了上游前端产物（覆盖了 `front/`） | 第 5 节 |
| 打开就要密码 | 部署的是上游 `latest`（没带免密补丁） | 用 `agent/dsh/local-merge` 或含该补丁的镜像 |
| 私有镜像永远"已是最新" | 没凭据 / Docker Hub 不通 / 走了加速站 | 第 1 节凭据 + 代理，且代码走 daemon digest |
| `compose pull` 报 pull access denied | `/root/.docker/config.json` 被 fnOS 清空 | 第 4 节 |
| 点"更新"后 dc 自己停了 | **dc 不能更新它自己**（会把自己 kill 掉） | 更新 dockercopilot 请在宿主机 `docker compose pull && up -d` |
